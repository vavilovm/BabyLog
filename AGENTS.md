# Delivery

For feature requests, complete appropriate checks, commit and push the changes,
and publish the signed APK through the existing GitHub release workflow. Verify
that the release completes and includes its APK before reporting completion.
Preserve the existing signing identity so users can upgrade in place.

The project owner explicitly authorizes pushing completed, checked changes to
`main` and publishing signed APK updates through this workflow as the normal
completion of feature and bug-fix requests. Do not ask for separate release
confirmation unless the user limits delivery for the current task. This standing
project preference was confirmed on 2026-11-06; platform approval checks still
apply and cannot be disabled by repository instructions.
